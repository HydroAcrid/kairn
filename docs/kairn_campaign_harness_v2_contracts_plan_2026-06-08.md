# Kairn Campaign Harness V2 Contracts Plan

Date: 2026-06-08

## Summary

The fast campaign harness is now useful as a v1 runner: it can execute proxy checks, mock/live proof entries, MCP smoke entries, endurance entries, official aggregation entries, bounded parallel workers, resumable artifacts, worker packets, summaries, CSVs, and cleanup.

The next improvement should make it harder to misuse. The goal is to turn the harness from a faster benchmark runner into a more rigorous evidence instrument.

Core principle:

> Manifests are human-authored. Rows are machine-executed. Artifacts decide what evidence can be claimed.

## Current Status

Implemented v1:

- `kairn bench campaign run`
- `kairn bench campaign summarize`
- `kairn bench campaign cleanup`
- Manifest validation
- Proxy stage
- Live proof/control entries
- Endurance entries
- MCP smoke entries
- Official evaluator aggregation entries
- Bounded worker pool
- Pause rules
- Resume from passed raw artifacts
- Worker packet export
- Raw/work artifact directories
- Summary/results/failures/proxy CSV output
- Cleanup for campaign-owned disposable workspaces

Remaining issue:

- The harness still treats manifest entries as the main execution unit. That is workable for v1, but weak for repeat-level scheduling, mode-level summaries, subagent packets, resource-specific concurrency, and locked resume behavior.

## V2 Goals

- Normalize every campaign into executable rows before work starts.
- Lock campaign inputs before execution.
- Persist row state explicitly.
- Separate internal signal from public evidence in the schema.
- Make quality/safety buckets more prominent than token savings.
- Support resource-specific parallelism.
- Make worker packets read-only by design.

## 1. Normalized Campaign Rows

Add an internal `CampaignRow` model generated by a planner.

```ts
type CampaignRow = {
  campaignId: string;
  campaignHash: string;
  rowId: string;
  entryId: string;
  entryType: "proxy" | "proof" | "endurance" | "mcp_smoke" | "official_eval" | "control";
  stage: "proxy" | "live" | "official";
  mode: string;
  repeatIndex: number;
  root: string;
  suite?: string;
  taskId?: string;
  tags: string[];
  workspaceId: string;
  artifactDir: string;
  logPath: string;
  timeoutMs: number;
  expectedFailureClass?: string;
};
```

Planner rule:

> A manifest entry can describe a suite, repeat, mode set, or official aggregation. The planner expands it into concrete rows with stable ids.

## 2. Campaign Plan Command

Add:

```bash
kairn bench campaign plan --manifest <path> --out-dir <path> [--json]
```

Keep `run --dry-run`, but make `plan` the first-class lifecycle step.

Plan output should include:

- resolved defaults
- expanded rows
- command previews
- artifact paths
- workspace ids
- resource plan
- pause rules
- cleanup policy
- evidence claim defaults

## 3. Manifest Locking

When a campaign starts, write:

```text
campaign-manifest.json
campaign-manifest.lock.json
```

The lock file should include:

- original manifest hash
- resolved defaults
- expanded rows
- Kairn git SHA
- Kairn package version
- Node version
- OS
- model default
- command hashes
- resource policy

Resume rule:

> `--resume` uses the locked manifest by default. If the source manifest changed, report the mismatch instead of silently mixing campaigns.

## 4. Row State Machine

Add durable row status files:

```text
row-status.json
```

Row states:

```ts
type CampaignRowStatus =
  | "planned"
  | "running"
  | "passed"
  | "failed"
  | "timed_out"
  | "classified"
  | "skipped"
  | "blocked"
  | "cancelled";
```

Campaign states:

```ts
type CampaignStatus =
  | "planned"
  | "running"
  | "paused"
  | "failed"
  | "completed"
  | "cleaned";
```

Resume rule:

> Resume should read row status, not infer state from partial JSON presence alone.

type CampaignRowMetrics = {

## 6. Hard Separation Between Signal And Proof

Build claim eligibility into artifacts.

Default policy:

| Stage | evidenceClaimAllowed | latencyClaimAllowed | Notes |
| --- | --- | --- | --- |
| `proxy` | false | false | internal routing/scope signal only |
| parallel `live` | false | false | useful improvement signal, not public proof |
| serial controlled `live` | maybe | maybe | only with clean quality/scope/token accounting |
| `official` fresh slice | true | true if cleanly measured | public evidence candidate |

This prevents fast iteration artifacts from accidentally becoming website or launch claims.

## 7. Safety-First Summary Buckets

Campaign summaries should lead with quality/safety, then savings.

Primary matrix:

```text
baseline pass / Kairn pass
baseline pass / Kairn fail
baseline fail / Kairn pass
baseline fail / Kairn fail
```

Then:

- clean savings
- quality rescues
- harmful assists
- token regressions
- scope violations
- MCP broad fanout
- MCP missing attribution
- harness failures

Savings should not be the first headline in internal campaign summaries.

## 8. Sharper Proxy Classifications

Current v1 proxy classes are enough for smoke testing, but v2 should make each proxy failure actionable.

Suggested set:

```text
proxy_pass
wrong_surface
scope_too_broad
scope_too_narrow
over_context
under_context
premature_suppression
missing_evidence_request
unnecessary_evidence_request
stale_context_risk
mcp_broad_fanout
mcp_missing_attribution
guardrail_valid
harness_failure
```

Goal:

> Proxy should not just say pass/fail. It should tell us what product behavior needs fixing before live spend.

## 9. Resource-Specific Parallelism

Global `--parallel 3` is too blunt for all stages.

Add:

```ts
resources?: {
  maxParallelProxy?: number;
  maxParallelCodex?: number;
  maxParallelDocker?: number;
  maxParallelMcp?: number;
  maxParallelOfficialEval?: number;
};
```

Recommended defaults:

- proxy: 6-8
- mock live: 3
- real Codex: 2-3
- MCP: 2-3
- official evaluator: 1 unless proven safe
- latency-sensitive rows: 1

## 10. Pause Rules After Every Row

The v1 worker pool already has a shared pause flag. V2 should make this a hard scheduler contract:

```text
row finishes
  -> classify
  -> update summary
  -> evaluate pause rules
  -> stop scheduling new rows if paused
```

Already-running rows may finish. New rows must not launch after pause.

Important pause classes:

- baseline pass / Kairn fail
- repeated harmful assist
- repeated token regression class
- repeated MCP broad fanout
- scope violation
- repeated Docker/evaluator/harness failure

## 11. Latency Discipline

Parallel runs should not create public latency claims.

Summaries should separate:

- throughput elapsed time
- wall-clock elapsed time
- per-row elapsed time
- Kairn overhead
- model elapsed time
- tool elapsed time
- latency claim eligibility

Useful formulas:

```text
net_speedup_ms = baseline_wall_clock_ms - kairn_wall_clock_ms
```

Kairn wall-clock time must include Kairn routing, retrieval, governor, MCP, and hook overhead.

## 12. Read-Only Worker Packets

Worker packets should encode constraints for subagents.

```json
{
  "packetId": "campaign-001-live-auth-003",
  "command": "kairn bench campaign run --manifest ... --stage live --parallel 1 --only auth-003 --json",
  "artifactDir": "/tmp/kairn-campaign/live/auth-003",
  "allowedActions": ["run_command", "collect_artifacts"],
  "forbiddenActions": ["edit_source", "edit_manifest", "delete_artifacts"],
  "return": ["campaign-summary.json", "results.csv", "failures.csv"]
}
```

Rule:

> Subagents can run packets and return artifacts. They do not change code or manifests.

## 13. Cleanup Contract

Cleanup should only remove campaign-owned disposable workspaces.

Rules:

- row artifacts must be written before cleanup
- workspace ids must be recorded
- cleanup must never remove source repos
- cleanup must never remove raw artifact dirs unless explicitly requested
- `--dry-run` should show all targets

## Implementation Order

1. Add `campaign plan`.
2. Add `CampaignRow` and expanded row planner.
3. Add `campaign-manifest.lock.json`.
4. Add row status files.
5. Convert v1 artifact writing to row artifact schema.
6. Add `evidenceClaimAllowed` and `latencyClaimAllowed`.
7. Add safety-first summary matrix.
8. Add resource-specific concurrency.
9. Expand proxy classifications.
10. Harden worker packet read-only constraints.

## Acceptance Criteria

- `run --resume` cannot silently mix changed manifests.
- Every executed unit has a stable row id.
- Every row has a status artifact.
- Every row declares whether it can support public evidence claims.
- Public-claim-eligible rows are never generated by proxy runs.
- Parallel campaigns stop scheduling new rows immediately after pause rules trigger.
- Summaries make harmful assists and scope violations more visible than savings.
- Worker packets are safe to hand to subagents without allowing code edits.

## Non-Goals

- Do not replace publication-grade official evidence.
- Do not make proxy results public claims.
- Do not use subagents as a substitute for deterministic harnessing.
- Do not start semantic slicing work inside this harness hardening pass.

## Bottom Line

The v1 campaign harness helps Kairn iterate faster.

The v2 contracts should make the same harness harder to fool.

That matters because Kairn evidence needs to be credible internally before it can be credible publicly.
