# Kairn Governance

Kairn is currently maintainer-led. The maintainer sets release scope, reviews contributions, manages security disclosures, and may delegate repository roles as the contributor community grows.

Technical decisions follow these priorities:

1. Verified coding quality and required-source recall.
2. Local, accountless operation and a narrow privacy boundary.
3. General repository evidence mechanisms over benchmark-specific rules.
4. Backward-compatible CLI, hooks, and MCP behavior.
5. Token and time reductions that survive quality gates.

Substantial interface or architecture changes should be proposed in an issue or design document before implementation. Decisions and their evidence should remain reviewable in the repository. Governance changes require a reviewed pull request and must not retroactively alter contributor licensing.
